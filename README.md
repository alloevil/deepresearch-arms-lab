# deepresearch-arms-lab

**能不能让一个弱的中文基座模型,在做 deep research(自主检索+写报告)时,
既写得好、又不瞎编引用?** 这个仓库是围绕这个问题做的一系列对比实验:
14 个 prompt/pipeline 方案("arm"),同一套评测体系,在同一个弱基座模型
(小米 MiMo 2.5 Pro)上跑同一批中文调研题,记录哪些机制真的有效、哪些看起来
合理但实测无效。

交互式结果面板(纯静态,双击 `dashboard.html` 或用任意静态服务器打开即可,
不需要联网/不需要后端):散点图看质量-可信性权衡、条形图看排名、时间线看
实验推进过程、点击任意 arm/题目能看到问题原文+报告全文+评分理由。

## 核心发现

1. **弱基座上,"模型写作时自觉遵守引用协议"这条路走不通。** 让模型自己维护
   一份"关键论断登记表"(F9.1)本质上是给它加了一条重协议,弱基座守不住——
   句级支撑率反而从裸模型的水平原地踏步,耗时翻倍。行业里(Anthropic 的后置
   CitationAgent、Perplexity 的检索层预绑定引用)也没有谁在赌"模型自觉"。

2. **可信性问题,可以靠 pipeline 结构解决,但要分阶段付认知账。** 三个方向
   都被验证有效:①**引用后置化**(F10.2 = 裸模型写完,独立一道核修工序核对/
   标记引用)——覆盖修复 +诚实标注,质量分基本不掉;②**采集侧预引用**
   (F11 = 检索时机械编号,写作时只填标号不编 URL)——错位/矛盾结构性清零,
   忠实度冲到全场最高(0.73 vs 裸模型 0.47);③**研究写作分离 + 上述两者叠加**
   (F115 = 预引用研究 → 无网写作 → 后置核修,三个 pass 分别只担一种职责)——
   在 n=10 题上同时超过裸模型的报告质量(+0.66)和引用忠实度(+0.20)。

3. **单个写作 pass 里不能既要广度又要纪律。** 尝试往 F11 的写作阶段里加
   "允许背景知识"、"放宽单源上限"、"强制原子句拆分"三次(F11.1/F11.2/F11.3),
   全部让忠实度变差——不是实现细节问题,是同一个 pass 的认知预算就是不够,
   这条边界在三次独立扰动里稳定复现。

4. **"诚实"在裁判眼里不一定是优点,这个效应会随题目难度放大,必须如实报告。**
   把题库从 10 题扩到 15 题(其中 5 题借自 DeepResearch Bench,见下方致谢)后,
   F115 的报告质量优势从 +0.66 收窄到 +0.12。根因很清楚:新题里有一道冷门的
   工业供应链题(地铁碳滑板供应商份额),公开可检索资料本来就稀薄——F115 的
   "没读过不得写"纪律诚实交了白卷(裁判评语:"只诚实标注了检索失败…未能
   交付任何有效答案"),裸模型没有这层约束,靠参数化知识垫出一份读起来完整、
   来源却对不上的报告,反而分数更高。**这不是新缺陷,是可信性收益本身的
   代价**:检索覆盖不足会被直接暴露成看得见的空洞,而不是被悄悄糊过去。
   结论方向不变(F115 仍是双优方案),但幅度对题目难度分布敏感,不应该用
   单一数字描述"稳定优势"。

## Arm 对比表

评测体系:judge = Claude Opus 4.8 盲评 ×3 取中位;fact = fact-v2 子句级
支持率(抓取引用页面原文比对,同一 4K 抓取长度口径全 arm 一致)。**n 是
判读时必须看的一列**——同一 prompt 下 judge 分数的 run-to-run 方差实测
约 1.0,n=3 的探索性结果只作方向参考,不是定版结论。

| Arm | 机制 | judge | 忠实度 | n | 备注 |
|---|---|---:|---:|---:|---|
| B | 裸执行(无引用协议) | 8.09 | 0.47 | 15 | 基线 |
| B3 | + 引用协议 prompt | 8.04 | 0.48 | 10 | 早期模型上的增益未迁移到弱基座 |
| F9.1 | + 生成时关键论断登记 | 8.13 | 0.48 | 10 | 负结果:弱基座守不住逐字登记协议 |
| F10 | 引用后置化(撤协议) | 7.58 | 0.72 | 3 | 精度赢但覆盖塌 |
| F10.1 | F10 + 检索纪律 | 7.75 | 0.53 | 3 | 核对吞吐成为新瓶颈 |
| **F10.2** | **B 原样 + 独立后置核修** | **7.69** | **0.58** | **15** | **轻量交付方案:覆盖修复+诚实标注,质量分基本不掉** |
| F10.3 | F10.2 + 核修曝光加大 3× | 8.00 | 0.41 | 3 | 负结果:曝光杠杆无效 |
| **F11** | **采集侧预引用**(只写读过的编号) | **7.88** | **0.73** | **15** | **可信性极点:错位/矛盾结构性趋零,代价是检索缺口会暴露成质量分损失** |
| F11.1 | F11 + 广度配额 | 7.54 | 0.68 | 3 | 负结果:源多时编号张冠李戴 |
| F11.2 | F11 + 允许背景知识双通道 | 8.83 | 0.74 | 3 | 负结果:纪律被绕过,矛盾回潮 |
| F11.3 | F11 + 强制原子句拆分 | 8.60 | 0.55 | 3 | 负结果:诱导更多弱接地断言 |
| F11.4 | 研究/写作分离(F115 前身) | 8.83 | 0.68 | 3 | 双优中间态 |
| **F115** | **预引用研究 → 无网写作 → 后置核修** | **8.21** | **0.69** | **15** | **最终交付方案:n=15 上双轴同超基线,幅度对题目难度敏感(见"核心发现"第4点)** |
| G | GPT-Researcher(外部成熟系统)+ 同一弱基座 | 5.75 | 0.45 | 3 | 初步观察(n=3,非定版):榜单强者迁移不过弱基座+中文+自有检索源三重环境差 |

## 架构

```
common/    LLM 调用、搜索、网页读取、引用核验的公共能力
eval/      题库(questions.json + questions_ext.json)、总控脚本 run.py、裁判 judge.py
arms/      每个对比方案的实现,一个方案一个文件
tests/     单测
scripts/   聚合/复现用的辅助脚本(见下方"复现指南")
dashboard.html + qa_data.json   静态可视化面板,数据已内嵌,双开即用
EXPERIMENTS.md   完整实验日志(比 README 细得多,含每一步的失败和判决)
```

F115(最终交付方案)的三阶段管线:

```
① 预引用研究(可上网)          ② 无网写作(工具层物理隔离)      ③ 后置核修(可上网)
   read 页机械编号 [Sn]     →     只能从①的笔记里抄标号    →    核对①②产出的每条引用,
   写入 notes.md                  不能编 URL、不能上网              标不出证据的标"[未证实]"
```

## 复现指南

本项目开发时用的是内部 LLM 网关,但代码里没有任何硬编码依赖——所有网关地址
和模型名都是环境变量,读官方 Anthropic/OpenAI API 一样能跑:

```bash
cp env_example.sh env.sh
# 编辑 env.sh:把 ANTHROPIC_BASE_URL 换成 https://api.anthropic.com(或你自己的
# 兼容网关),ANTHROPIC_AUTH_TOKEN 换成你的 key;不需要的变量(如 LAB_CLAUDE_BASE_URL)
# 直接删掉,代码会落回标准端点。
source env.sh
python3 -m pip install -r requirements.txt
python3 -m eval.run --arms B,F102,F11,F115 --questions q01,q02 --tag my_run
python3 -m eval.run --judge results/my_run --samples 3
python3 -m eval.run --fact results/my_run --v2 --arms B,F102,F11,F115
python3 scripts/dash_agg.py      # 重新聚合统计
python3 scripts/dash_qa_build.py # 重新生成 dashboard 用的 qa_data.json
```

Arm G(GPT-Researcher 对照)额外依赖 `gpt-researcher` 包和你自己的
`.venv`,不在默认依赖里,见 `arms/arm_g_gptr.py` 头部注释。

## 已知局限(如实披露)

- **没有 token/成本埋点。** `meta.json` 里的 `tokens.in/out` 字段恒为 0——
  这一轮实验没有做用量统计,`avg_secs`(每题耗时)是唯一的成本代理指标。
  "多跑几个 pass 换可信度值不值"这个问题,本仓库目前只能回答延迟侧,不能
  回答 token 成本侧。
- **GPT-Researcher 对照只有 3 题**,标"初步观察"而非结论,样本太小,
  不足以支撑"外部系统在弱基座上必然失败"这种强断言。
- **judge 分数本身有 run-to-run 方差**(同 prompt 重跑,实测 ~1.0),
  任何两个 arm 的比较都应该看 n 和方差,不要只看点估计。
